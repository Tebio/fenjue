## 0. 用户画像与硬约束

- A 股散户，盘中盯盘，短线（1-3 天）+ 收息底仓双线并行
- T+1、主板为主、涨跌停 10%
- 已知行为弱点（本人自认）：回本心理位易情绪化操作、盘中容易追问"要不要跑"
- 对系统的核心诉求：**给一个持仓，大跌/大涨/横盘时给出「持有/减仓/清仓 + 依据 + 作废条件」的可执行判断**，而不是只给价位表

## 1. 体系架构（现状）

```
数据层：baostock 8 年前复权全主板日K（big_kcache，~2500 只）
        + 时点流通市值（cap_hist，换手率反推）+ 全分红史（dividend_history）
        + 实时：新浪 hq.sinajs 批量快照（3195 只 7 秒，唯一稳定通道）
周期层：regime_meter 盘后判周期（主线/妖股/恐慌/平淡，样本外复验过）

持仓处置层：⚠️ 最薄弱——只有人工纪律位 + 启发式清单（见 §5）
```

## 3. 已证伪/负期望清单（别碰）

- 竞价追首板次日：**-0.67%/38.9%**（n=813），带板块龙头更差
- 伪缠论 B1（分型+MACD 背驰+缩量）：T+1 46.5%/-0.03%，**跑输一行"跌 3%"**
- 连板妖股水下低吸：当日 +0.22% 但 T+1 下物理不可达；持有到次日 **-1.57%/37.8% 全灭**
- 盘中止盈 2%：胜率更高但均值全转负（赢次数输钱，右尾被砍）
- 焚诀 V2 追高门：全周期跑输随机（45.8% vs 48.3%）

## 4. 实盘影子验证记录（最近一周，全部真实结算）

- 9/8 名单→9/9 执行：n=80，胜率 35.0%，均值 **-1.15%**
- 9/9 名单→9/10 执行：n=182，胜率 19.8%，均值 **-1.65%**
- 结论：退潮/妖股段反转族连续挨打，46 万基率不证伪，但实证了「需要周期闸门」
- 待立项：周期仪判退潮/妖股 → 反转族名单降级/停牌 + 8 年分组回测

## 5. 持仓处置现状（用户痛点区，诚实披露）

**目前只有这些，且大多是启发式、未经系统回测：**

1. **三级止盈位法**：找前高/阻力集群/支撑/整数关 → 保守/激进/保本三档表达（框架成熟，但无量化胜率）
2. **深水洗盘检查**：开盘急跌>4% 时拉 60 天 K 线数历史洗盘次数与拉回率（启发式，未回测）
3. **出货信号四步**：量价背离/冲高回吐速度/板块联动/大盘环境（盘中人工判断）
4. **利空反涨六范式**、**加速赶顶九信号**（references 里有清单，触发时人工对照）
5. **用户自定义纪律位**：如宝丰能源「成本 25，22.8 收破割，反抽 23.8-24.4 减」——人工预设，系统只在越线时报警（持仓哨兵已实现报警，不给决策）

**实际暴露的问题（2026-09 实录）**：
- 宝丰 25.35 区间顶盘中突破→收 24.70 失败→次日 -2.9% 收 23.97 破假突破线，系统只能报"破线了"，给不出"假突破后未来 3 天继续下行概率 X%"
- 大涨日（如单日 +5%）系统没有「兑现 or 持有」的统计依据

## 6. 决策纪律（现行，人工执行）

- 开盘前 30 分钟不下方向结论（2026-07-20 长电事件血训）
- 周期×玩法矩阵：主线期可尾盘买强票；妖股期默认不参与；恐慌期空仓或只做高股息+反转减半
- 候选池超 1 个交易日提示、超 3 日拒绝继续筛
- 消息股按公告原文对账 + 给作废条件
- T+1 提示强制附带

## 8. 给审查员的任务书

**设计目标：持仓处置决策模块**。输入一只已持仓股票的：成本价、现价、持仓天数、当日涨跌幅、量能、所属板块状态、大盘周期、个股事件（公告/利空/利好），输出：

1. **持有/减仓/清仓 三档建议 + 概率依据**（例如"假突破后 3 日内继续下行概率"这类可回测的统计量）
2. **明确的作废条件**（什么信号出现则判断失效）
3. **必须可回测**：用现有 8 年 big_kcache 数据能跑出胜率/均值/样本量，拒绝无数据支撑的经验法则
4. **必须过 T+1 物理检查**：任何"当日买当日卖"式的 edge 对新开仓不可达
5. **防过拟合**：样本内/样本外切分（2019-2022 / 2023-2026）+ 随机对照组

**优先回答的三个具体问题**：
- 持仓票单日大跌（-3%/-5%/-7% 分档）：跑还是留？历史统计上「大跌后次日/3 日走势」与什么因子相关（趋势环境/量能/板块/是否破前低）？
- 持仓票单日大涨（+5%+）：兑现还是持有？「强势日次日溢价」在不同周期下的表现？
- 「假突破」（盘中破前高但收回线下）之后的期望走势？现有纪律是"收破就走"，这个规则的期望值是多少、能否优化？

**审查约束**：以上数字均可复跑（仓库 /opt/data/fenjue，引擎 engine/entryexit_matrix.py 等）；新主张必须自带回测证据，否则标注「假设」。
