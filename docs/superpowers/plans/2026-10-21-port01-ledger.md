# PORT-01 统一组合账本 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建 `engine/portfolio/ledger.py`——所有线共用的账本，逐笔现金守恒，输出净值曲线/逐年贡献/资金占用。它是 RISK-01/UI-01/PORT-02/03/CASH-01/MID-02 的唯一输入。

**Architecture:** 纯记账层，零业务规则（排序/止损留在 lines/）。Fill 进、Ledger 记账、mark-to-market 出 nav_series。费用走 `engine/costs.py`（TAX-01 实际落地形态——**spec 里写的 taxfee/ 是旧计划名，真源是 costs.py**，别建 taxfee 目录）。账本一律用成交价/原始价，复权口径是调用方责任。

**Tech Stack:** Python 标准库 dataclasses + json；`engine/costs.py`（buy_fee/sell_fee/dividend_tax_rate）；pytest

**Spec:** `docs/plan/specs/PORT-01-portfolio-ledger.md`

## Global Constraints

- **账本不塞业务规则**（spec 风险条）：不排序、不止损、不选股——只记账
- **现金守恒是硬断言**：`assert_conservation()` 误差 < 0.01 元，不成立直接 raise（#249「买入漏扣现金→8年净值8377%」是这条存在的理由）
- **透支必须 raise**（反例）、**重复 (line, code, day, side) 必须 raise**（反例）
- 费用口径必须走 `engine/costs.py` 的公开函数——先读它确认函数名签名，不许自己另算
- 解释器 `/opt/data/fenjue/.venv/bin/python`；测试 `cd /opt/data/fenjue && .venv/bin/python -m pytest tests/test_ledger.py -q`
- A股股数 100 整数倍（Fill.shares 校验）

## Review Focus

1. **守恒断言的完备性**：买入扣 cash+fee、卖出加 cash-fee-tax、分红加 cash-tax——每个分支都要进守恒式（#249 是漏扣买入现金）
2. **重复入账防线**：历史 bug 源，必须 raise 不许去重吞掉
3. **费用口径一致性**：与 costs.py 对拍（同一笔 Fill 手算费 vs costs.py 输出）
4. **pead_pool 对照的解释义务**：±0.5% 内算一致；超了必须逐笔找出差异写差异台账，不许调参凑
5. **私有路径读取**：SEC-01 后账本输入可能来自 data/private/——load_line_fills 不硬编码路径
