## 0. 接手者先读 `START-HERE.md`（5 分钟定向）

本文件是**总纲（背景与路线）**，不是入口。入口是 `START-HERE.md`：它给出阅读顺序、三条铁律、当前阶段门、权限边界、"直接开干的七个坑"。

### 0.1 文档所有权（**单一定义**，防止文档自己出现"口径重复"）

| 事实/规则 | **唯一**定义处 | 其他文档只能 |
|---|---|---|
| 数据契约（路径/字段/单位/精度）| `INTERFACES.md` | 引用，禁止复述 |
| 硬约束（禁复活清单/纪律）| `CONSTRAINTS.md` | 引用 |
| 已冻结决策与反证条件 | `DECISIONS.md` | 引用 |
| 验证判据与门的放行命令 | `VERIFY.md` | 引用 |
| 任务队列与验收标准 | `backlog.yaml` | 引用 |
| 当前阶段门 | `STATE.yaml` | 引用 |
| 模块边界与依赖规则 | `module-layout.md` | 引用 |
| 历史事实与结论 | `AGENTS.md`（只增不改）| 引用编号 |

**任何"同一事实写两处"的改动＝违规**（两处必然漂移，这正是 #262-C 的病根）。

### 0.2 工作流（6 步）

1. 读 `START-HERE.md` → 确认当前 `STATE.yaml.current_gate`。
2. 从 `backlog.yaml` 挑 `gate == current_gate` 且 `depends_on` 全 `done` 的条目（按 `priority`）。
3. 看 `specs/<ID>*.md` 拿契约；**没有 spec 先写 spec**（用 `specs/_TEMPLATE.md`）。
4. 实施 → `bash scripts/verify.sh` + 跑 spec 验收命令 → **必须有真实输出**。
5. 落两处账：`AGENTS.md` 追加新编号 + `backlog.yaml` 改 `status/evidence`。
6. 若该门全部验收通过 → 更新 `STATE.yaml.current_gate` 并在台账记录门验收输出。

**硬红线**：不改 `lines/` 已注册线的规则（走 `DECISIONS.md` 变更流程）；`core/` 不得 import 上层；
费用税费只能来自 `taxfee/`（禁止新的 `0.15` 字面量）；生产只能调 `registry` 里 `LIVE` 的线；
持仓/资金/台账不进公开仓库（`INTERFACES.md I7`）。

## 1. 机构量化平时在干嘛：七个部门 + 三个委员会

| 部门 | 日常干什么 | 每日/每周产出 | 依赖的系统 |
|---|---|---|---|
| **数据部** Data | 数据落地、字段对账、异常巡检、PIT 快照、源冗余切换 | 数据完备性日报、异常清单 | 数据平台（PIT 库 + 质量监控） |
| **研究部** Alpha Research | 假设→事件研究/因子检验→回测→上会材料；文献与另类数据 | 候选信号报告（IC/胜率/容量） | 回测框架 + 事件工具箱 + 试验登记 |
| **组合部** Portfolio Construction | 资金分配、跨线冲突、仓位与成本、现金管理 | 目标仓位/委托单 + 资金占用表 | 组合账本 + 成本模型 |
| **风控部** Risk | 敞口/相关性/波动率目标/回撤预算/压力测试 | 风险日报（敞口、相关性、预算使用率） | 风险模型 + 归因引擎 |
| **执行部** Trading / Execution | 下单、成交质量、滑点归因（TCA）、券商关系 | 成交回执 + 滑点统计 | OMS/EMS + TCA |
| **中台** Middle Office | 对账（成交/持仓/费用）、净值、费用与税、异常处理 | 日终净值 + 对账差异清单 | 对账系统 + 会计口径 |
| **技术部** Quant Dev / Infra | 研究→生产的工程化、统一库、调度、监控告警、事故复盘 | 生产变更 + 监控面板 | 调度/监控/CI |
| 委员会① **策略评审会** | 新线上会（证据够不够）、参数变更、退役决策 | 会议记录 + 状态变更 | 策略登记与状态机 |
| 委员会② **风险委员会** | 风险预算、限额、极端场景预案 | 限额表 | 风控系统 |
| 委员会③ **投决会** | 大方向与资金总量（一个人时＝自己裁决，但**留痕**） | 决议 | 台账 |

**关键认知**：机构不是"一个前端 + 一个模型"，而是**七条流水线 + 三次例会**。
散户/个人的差距通常不在研究（他已经很强），而在**中台、风控、执行归因、治理**这四块"不性感但决定钱"的地方。

## 5. 治理：策略状态机与变更流程（防乱的核心机制）

**状态机（写进 `engine/registry/`，成为代码而非文档）**

```
IDEA → RESEARCH（探索中，不出票）
     → CANDIDATE（有全样本证据 + 四件套体检，可进影子）
     → SHADOW（前向影子账本，只记账不出票）
     → LIVE（可出票，进组合）
     → ICU（跑输/衰减，降暴露，只观察）
     → DEAD（退役，进证伪墓地，禁止复活）
```

**变更流程（任何对 LIVE 线的规则改动）**
1. 写变更提案（改什么、为什么、预期影响）
2. 在**样本外**（holdout/rolling）验证，不得只用原来的全样本
3. 记录到 `AGENTS.md` 新编号 + `backlog.yaml`
4. 通过后 `registry` 升版本号；**旧版本留档**（便于归因"是版本变了还是市场变了"）

**退役判据（机械，替代人判）**：滚动 60 交易日超额 t 值 < 0 且 |滚动 Sharpe| < 0.3 持续 20 个交易日 → 自动降 ICU；再持续 40 日 → 自动 DEAD（并发通知）。

## 7. 个人量化 ≠ 缩小版机构（先看这节，别照抄）

**把话说清**：§1–§2 的"七部门"是**思考脚手架**（用来定位"哪个功能没人管"），**不是要建的七个摊位**。
个人照部门去建，会得到机构**所有**的弊端，却拿不到任何一条弊端对应的资源（人、数据、资本、牌照）。

### 7.1 机构的弊端（是"病"，不要抄）

| 弊端 | 机制 | 对你的提醒 |
|---|---|---|
| 代理问题 / 职业风险 | 员工为"不被开除"交易：抱团拥挤因子、季度末粉饰、亏的不敢砍／赢的过早锁 | 你没有这问题（P&L 是唯一指标）——**这是结构性优势，别用"像机构"把它换掉** |
| 委员会稀释 alpha | 决策回归共识、限额层层加码 → 组合向指数靠拢 | 不设"委员会"：改成一页 checklist + 台账留痕 |
| 规模杀死 alpha | 规模↑ → 只能往流动性好的大票挪 → edge 稀释；且营销要规模 | 你的上限是**小市值流动性**不是 AUM → 要容量曲线，不要"扩规模" |
| 固定成本基数 | 终端/数据/薪水 → 逼着做大 AUM | 你边际成本≈0 → **薄 edge 也值得做**（深档年均 2 次也值） |
| 合规/流程惰性 | 改一个参数要走数周 | 你 1 小时能上线 → **但必须补留痕+样本外**，否则优势变灾难 |
| 指标错位 | 盯 Sharpe / 相对收益 / 一年考核 → 短视、砍掉慢策略 | 你只该盯**绝对钱的曲线 + 回撤预算** |
| 数据/技术债 | 老系统没人敢动，和稀泥 | 你也有（494 脚本、109 个 `0.15`）→ 用断言与回归测试替代人情判断 |
| 杠杆 + 拥挤 | LTCM / Archegos 式强制平仓 | 你不用杠杆 —— 天然免疫（保持） |
| LP 行为 | 回撤期被赎回，在最坏点位被迫减仓 | 你没有 LP —— **可以拿得住恐慌低点**（深档线的存在前提） |

### 7.2 你的结构性优势（机构做不到的，要主动用）

1. **容量套利**：只做机构装不下的（小市值 / 微盘注意力 / 低频深档）。深档线 8 年 15 次触发＝机构无法向 LP 解释"99% 时间空仓"，你能。
2. **税筹**：A 股持满 1 年免红利税 → 股息锚线可把**持有期与税级挂钩**（机构资金有期限，做不到）。
3. **无期限**：PEAD 20 日、股息锚 12 个月都不受赎回压力。
4. **零固定成本**：薄 edge 仍是净收益。
5. **决策速度**：改规则到上线以小时计。

### 7.3 个人量化的真成本是**注意力**（所以：减法优先）

机构用**人**防错；你用**断言 / 测试 / 限额**防错。因此路线不是"补齐 40 条"，而是：
**先减法**（砍掉不产钱的 cron 与脚本）→ **再补四件必需**（账本 / 对账 / 限额 / 断言）→ **最后才谈前端**。

**注意力预算硬规则**
- 日常必须打开的看板 ≤ **1 个**
- 每日需人参与的动作 ≤ **3 个**（盘前确认、9:25 下单、盘后对账）
- 其余全部自动，**异常才推送**（推送到人＝需要裁决或需要动手，订阅式日报一律砍）

### 7.4 收敛为三层（替代七部门）

| 层 | 谁负责 | 内容 |
|---|---|---|
| **L1 数据层** | 机器 | 落地 + DQ 断言 + 源冗余 + 快照（异常才叫人） |
| **L2 研究层** | 人 + AI | 假设 → 事件研究 → 证伪 → 注册（探索与裁决） |
| **L3 生产/账本层** | 机器 | 账本 + 限额 + 对账 + 告警（只呈现结果与差异） |
| **接口** | **一页** | 周报/日报 10 行：净值、暴露、预算使用率、异常、待裁决 |

### 7.5 反向纪律（从弊端反推，写进制度）

- **复杂度上限**：新增一条线必须**先退役一条**（或给出"它什么时候死"的判据）；单模块 ≤ 400 行；**cron 总数不增**（新增必须合并）。
- **留痕优先于速度**：速度快是优势，但改 LIVE 线必须走"提案 → 样本外 → 台账 → 版本号"。
- **外部质询替代委员会**：每季度把**结论**（不是代码）打包给外部挑刺。
- **不做机构式**：部门、例会、委员会、日报邮件——一律不做（见 `backlog.yaml` 的 `not_doing` NT-07）。
