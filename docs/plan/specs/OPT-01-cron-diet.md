# SPEC · OPT-01 注意力减法审计（P1，G0，1 天）

## 目标
把现有 **63 个 cron job + 494 个脚本**按"**是否直接关系钱**"分类，产出一份**可暂停清单**（保留回滚、不删），
让"每日需人参与的动作 ≤ 3 个、只异常推送"可执行。这是 G0 除契约冻结外唯一允许做的事。

## 非目标
- **不删除任何 job/脚本**（只暂停/归档，随时可恢复）
- 不动排程时刻（会改变推送行为 → 需用户裁决，见 DECISIONS O-05）
- 不评价任何**研究结论**的对错（那是台账的事）

## 现状证据（为什么必须做）
- cron **63 个**（含 7 个"操作台重建"、5 个 HiThink/席位/板块类、转债/商品/期指基差/两轮等），
  其中 4 个已 paused 属回滚保险（`AGENTS.md #262-A`）
- 用户已明确：个人量化的真成本是**注意力**，不是算力（`#267`）
- 每日推送面：日报 + 雷达 ×3 时段 + 事件推送 + 操作台 ×7 + 影子/结算/审计… → 注意力被摊薄导致**漏执行**
  （实例：601137 防线 9/30 已破，几天没人动，`#265⑬`）

## 输入
- `/opt/data/cron/jobs.json`（63 条：name / schedule / script / deliver / 状态）
- `/opt/data/cron/executions.db`（最近 30 天：执行次数、失败率、是否触发过推送）
- `/opt/data/scripts/` 脚本清单

## 输出
1. `docs/plan/attention-budget.md`：全量分类表，字段：
   `id | 名称 | 排程 | 频率 | 类型(钱相关/研究相关/运维) | 近30天执行 | 近30天推送 | 建议(保留/降频/暂停/归档) | 理由`
2. `docs/plan/attention-budget.yml`（机器可读，供后续脚本读取白名单）
3. `AGENTS.md` 新编号条目（记录分类原则与暂停清单）

## 分类判据（写死，避免主观）
| 类型 | 判据 | 默认动作 |
|---|---|---|
| **钱相关** | 直接产出下单/卖出依据、持仓哨兵、资金或账本数据 | **保留** |
| **研究相关** | 只为研究攒数据/回测/审计，不直接影响明天的单 | 降频（周频/手动触发）|
| **运维** | 健康自检、数据落地、看门狗（静默）| 保留（但必须静默）|
| **重复/装饰** | 与另一 job 输出重叠（如 7 个操作台重建）、或只为人看且已有面板 | 暂停（保留回滚）|

## 验收
- 正例：三类（钱相关/研究相关/运维）分类表**覆盖全部 63 条**，无"未分类"
- 正例：最终"每日需人参与动作"清单 ≤ 3 条（盘前确认 / 9:25 下单 / 盘后对账）
- 正例：可暂停清单里每条都写清"暂停后谁会缺什么"（避免停掉上游导致下游静默吃旧数据，`#261` 教训）
- 反例（lint-ignore 说明）：把**上游数据 job**（kcache/m60/HiThink 落盘）暂停而保留其下游 → 必须被拒绝
  （检查方式：对每条"建议暂停"，扫描它的产出文件是否被其他 job 读取；是则不许暂停）
- 反例：`lint-ignore` 负例是"删除 job"——本条目只许暂停，删任务必须用户单独裁决
- 耗时：全量扫描 < 5 分钟

## 回滚方式
`hermes cron resume <id>` 逐条恢复；`attention-budget.yml` 即白名单，删文件不影响生产。

## 依赖 / 风险
- 依赖：无（可并行于 PLAT-00）
- 风险：暂停上游导致下游静默吃旧数据（`#261` 的教训）→ 用上面的"产出文件被谁读"扫描兜
- 风险：把"用户每天真的会看"的东西停掉 → 暂停前给出**完整清单让用户过目一次**（本条目产出物就是给他签字的）

## 工期
0.5 天扫描分类 + 0.5 天"谁读谁"依赖核对与成文
