# VERIFY · 验证契约（"完成"的唯一判据）

> 本文件定义**什么算完成**，以及每个阶段门的**放行命令**。任何"我改好了"都必须附这里的输出。
> 铁律：**没有真实命令输出的完成＝未完成**（#261 教训：字段层健康 ≠ 脚本真跑过）。

---

## 0. 总闸：`scripts/verify.sh`

一条命令跑完全部静态检查（G0 起生效）：

```bash
bash scripts/verify.sh            # 全量
bash scripts/verify.sh --fast     # 跳过较慢的回归
```

它至少做四件事，任何一项失败即退出码非 0：
1. **计划自检**：`docs/plan/tools/plan_lint.py`（悬空引用 / 缺 spec / gate 完整性）
2. **语法检查**：`py_compile` 全部 `engine/**/*.py` 与 `scripts/*.py`
3. **单元测试**：若存在 `tests/` 则 `pytest -q`（没有则 SKIP 并明示）
4. **回归基线**：若存在 `tests/golden/` 则比对关键数字（差异 > 0.1pp 失败）

**"完成"的定义**（四条缺一不可）：① 你的 spec 验收命令通过；② `verify.sh` 全绿；③ 落两处账（`AGENTS.md` 新编号 + `backlog.yaml` status/evidence）；④ 说明回滚方式。

## 2. 每个 spec 必须写清的验证项（模板见 `specs/_TEMPLATE.md`）

- **正例**：正常输入 → 期望输出（给出**具体数字/文件**）
- **反例**：非法/边界输入 → 必须报错或降级（不许静默通过）
- **对照**：与旧实现/独立实现比对（差异阈值 + 差异必须被解释）
- **耗时**：可接受的运行时长（跑批类必须给）
- **回滚**：出问题怎么退（保留旧文件 / git revert / 开关位）

## 3. 禁止的"伪验证"

| 伪验证 | 为什么不算 |
|---|---|
| 只跑 `py_compile` | 编译过 ≠ 逻辑对（#261 的脚本编译一直是过的） |
| 只跑一个样本 | 边界在长尾（最低佣金、一字板、停牌、跨月） |
| "我看日志没报错" | 静默吞异常是历史常态（#261 的 daily_news 就是） |
| 用**旧产物**验证新逻辑 | 必须用当前输入重跑 |
| 拿事件研究均值当验收 | 期望要过组合账本（D-13） |

## 4. 回归基线（golden master）

- 位置：`tests/golden/*.json`，每个文件对应一条已注册线的**关键数字**（收益、胜率、n、回撤）
- 生成：`python -m tests.golden.record <line>`（首次由人确认后冻结）
- 用途：改了 `core/`、`taxfee/`、`data/` 之后，若关键数字漂移 > 0.1pp → **测试失败**，必须解释（写进 `AGENTS.md`）
- 现状：**尚未建立**（PLAT-04）
