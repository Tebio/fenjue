> 2026-09-18 立。起因：用户质疑「胜率低是不是因为笼统测一遍」——要求逐条查历史测法，而不是重跑一遍。
> 数据来源：`data/claims_registry.yaml`(15 条主张) + `engine/*.py` 研究脚本的细分轴扫描 + `AGENTS.md` 各批记录 + 各批结果 JSON。

## 判读方法

对每个策略查三件事：**①当时用什么脚本测 ②口径（宇宙/期间/入场/出场/对照/成本）③分了哪些轴**。轴清单固定为：
`位置MA60 / 深度(跌幅档) / regime / 市值 / 量能 / 时间分段`。

**核心结论**：**12 个以上策略是被「笼统测一遍」判死的，其中 4 个族已有「细分后复活」的实证**——说明漏杀真实存在，不是理论担忧。

## 五、结构性原因（为什么会有漏杀）

1. **判死渠道不统一**：走 `law_pipeline` 的（六闸门全轴）判死是可靠的；但**联赛/临时脚本判死的信号从未进过管线**——它们只做了「双段+随机对照」，没有位置/深度轴。
2. **默认入场口径会误杀**：框架默认 `next_open`，而打板族成立的前提是 `signal_close`（close-entry）。用默认口径审打板系 = 测的是已证伪的「次日追」变体（-0.52%）。2026-09-13 已修（三口径 entry），但更早的判死结论**没有被重新审过**。
3. **「人群差异假象」反向也成立**：笼统样本里，正负不同质的子格互相抵消 → 整体≈0 → 判死。跌停接（+1.06% lump vs +5.09% 细分）就是典型。
